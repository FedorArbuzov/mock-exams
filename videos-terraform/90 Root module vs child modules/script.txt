The root decides where; child modules decide how.

The root module is the Terraform configuration you run from, usually for one environment or deployment boundary. It assembles providers, backend configuration, and child module calls. Child modules are reusable directories called by roots or other modules to implement a focused piece of infrastructure.

Keep environment-specific decisions, provider aliases, and state boundaries near the root. Keep reusable implementation details in child modules. This separation makes the same child module usable across development and production without forcing it to know account names, backend buckets, or organization-specific paths.

Putting backend configuration inside a reusable child module does not create separate state for each caller and misleads readers. Conversely, embedding production account decisions in a child module makes reuse brittle. Let the root own deployment context and the child own its implementation.

Roots own deployment context; children own reusable implementation.
