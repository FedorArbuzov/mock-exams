Why does kubectl create fail the second time you run it?

Because create is imperative and one-shot: it makes a new object, and if that object already exists, it errors with AlreadyExists. apply is declarative and idempotent: it creates the object if missing, and updates it to match your manifest if it already exists. Run apply a hundred times and the result is the same.

The deeper difference is how updates work. apply records your manifest as the last-applied configuration, so it can compute a three-way merge and change only what you changed. create has no such memory - it just refuses when the name is taken.

What beginners get wrong: scripting create in CI, which breaks on the second deploy. Or mixing create and apply on the same object, which confuses the last-applied tracking and can cause surprising diffs.

Practical tip: use apply for everything you manage from files. Reserve create for quick throwaway objects or generating YAML with dash dash dry-run equals client dash o yaml.

Rule to remember: create makes once, apply reconciles every time.
