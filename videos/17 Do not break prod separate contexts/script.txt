How do you avoid deploying to prod by accident?

Separate contexts with loud names. Call them kind-dev, staging, and prod - never cluster-one and cluster-two. Color your shell prompt with the current context if you can. Never reuse the same short alias for local and production.

What beginners get wrong: one shared context name after merging kubeconfig files, or running kubectl apply from muscle memory while Slack is distracting them. Production outages often start with a successful apply to the wrong cluster.

Practical checklist before apply: kubectl config current-context must show the expected name. kubectl get nodes should match the environment you think you are in. Prefer dry-run client or server when unsure. For prod, require a second confirmation in your head: namespace, context, and change.

Rule to remember: current-context before apply - every time, no exceptions.
