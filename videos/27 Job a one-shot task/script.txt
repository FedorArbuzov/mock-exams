How do you run a task once - like a migration - and have it actually finish?

A Job. Unlike a Deployment, which keeps Pods running forever, a Job runs a Pod to completion and records success or failure. When the container exits zero, the Job is Complete. If it fails, the Job retries up to backoffLimit before giving up.

Jobs can run in parallel too, with completions and parallelism, useful for batch work like processing a queue. Each attempt is a Pod, so you can read logs from every try.

What beginners get wrong: running a migration in a Deployment, which restarts it endlessly in a loop - the migration reruns every restart. Or seeing a Job Pod in Completed state and thinking it crashed. Completed is the goal, not an error.

Practical check: kubectl get jobs shows COMPLETIONS like 1 of 1. kubectl logs on the Job Pod shows what happened. Clean up with ttlSecondsAfterFinished so old Jobs do not pile up.

Rule to remember: run-once work belongs in a Job, and Completed means success.
