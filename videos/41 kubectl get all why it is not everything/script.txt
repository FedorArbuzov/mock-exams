Why does kubectl get all not actually show everything?

The name is misleading. kubectl get all only lists a small, common set of resource types in the current namespace - Pods, Services, Deployments, ReplicaSets, StatefulSets, and a few more. It deliberately skips a lot.

What it misses matters. ConfigMaps and Secrets are not there. Neither are Ingresses, PersistentVolumeClaims, ServiceAccounts, Roles, or any custom resources from operators. And cluster-scoped things like Nodes, PersistentVolumes, and Namespaces never show up, because get all is namespace-scoped.

What beginners get wrong: trusting get all as a full audit, then missing the ConfigMap or Secret causing the problem. Or forgetting cluster-scoped resources entirely during cleanup, leaving orphans behind.

Practical tip: to really enumerate, use kubectl api-resources to list every type, then query the ones you care about. kubectl get configmap comma secret comma ingress covers common gaps.

Rule to remember: get all is a shortlist, not an inventory.
