You have heard about Kubernetes, but what does it actually do?

Docker runs a container on one machine. Kubernetes runs containers across a cluster of machines and keeps them aligned with the state you declared.

You write something like: I want three replicas of this app, always running. Kubernetes stores that desired state, then controllers continuously compare it to reality. If a container crashes, a new one starts. If a node dies, workloads move. If traffic grows, you raise replicas and Kubernetes spreads the load.

So Kubernetes is not "Docker with extra steps." It is an automation system for placement, healing, and scaling.

Remember this one sentence: you declare the end state, Kubernetes fights to keep it true.
