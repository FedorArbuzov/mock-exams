What does a minimal working CI/CD for Kubernetes look like?

In simple terms, build an image, push to a registry, deploy the new version to the cluster.

Concretely, treat that as a testable rule: Build an image, push to a registry, deploy the new version to the cluster. When reality disagrees, trust cluster signals over the story in your head.

Delivery quality is a bored repeatable path: pinned image, Git as source of truth, sync, smoke, rollback.

If humans must remember secret dashboard clicks, drift is already invited.

Beginner trap: kubectl edit in prod with no path back to Git.

If someone asks tomorrow what this changes, answer with the rule: build an image, push to a registry, deploy the new version to the cluster.
