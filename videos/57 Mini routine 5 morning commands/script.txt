What should an on-call engineer check first each morning?

A five-command routine. First, kubectl get nodes - confirm the cluster is Ready. Second, kubectl get pods dash A, or at least your namespaces - scan for CrashLoop, Pending, and ImagePull problems. Third, kubectl get events dash A dash dash sort-by equals dot lastTimestamp - read the newest failures. Fourth, kubectl top nodes and kubectl top pods if Metrics Server is there - spot CPU or memory pressure. Fifth, kubectl rollout status on critical Deployments, or get deploy to see unavailable replicas.

That sequence answers: are nodes healthy, are workloads up, what broke recently, is capacity tight, did last night's deploy finish.

What beginners get wrong: opening twelve dashboards before a single kubectl get, or checking only one namespace while another burns. Or skipping events and guessing from Pod status alone.

Practical tip: save these as a shell alias or a small script. Run it before coffee. Add your team's namespaces and Deployment names so the routine matches your service map.

Rule to remember: nodes, pods, events, top, rollouts - five checks, then dig deeper.
