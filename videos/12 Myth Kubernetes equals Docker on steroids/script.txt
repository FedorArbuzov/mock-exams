It's just Docker on steroids, right?

No. Docker runs a container on one machine. Kubernetes orchestrates many machines: desired state, scheduling, networking, health checks, rolling updates, and access policy. Containers are the unit. The cluster is the product.

What breaks when you believe the myth: you think kubectl apply is docker run with YAML. Then a Pod is Pending, Endpoints are empty, or ImagePullBackOff appears, and Docker knowledge alone cannot explain it. You need nodes, kubelet, Services, and controllers.

Practical check: compare mental models. Docker Compose says start these containers together. Kubernetes says keep this Deployment at three healthy replicas forever, even if a node dies. That loop is not a bigger Docker daemon.

Rule to remember: Docker runs containers. Kubernetes runs the cluster contract around them.
