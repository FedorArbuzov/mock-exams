Need to change one field without rewriting the whole YAML?

kubectl patch. It updates specific parts of a live object with a minimal JSON or strategic merge patch. You do not open an editor and you do not re-apply a full manifest - you send only the change.

Classic uses: scale a Deployment, add an annotation, flip an image tag in a script, or toggle a feature flag field. In CI and automation, patch is cleaner than edit because it is non-interactive and easy to repeat.

What beginners get wrong: guessing the JSON path and silently patching the wrong nested field. Or mixing patch types - strategic merge, JSON merge, and JSON patch behave differently. Also patching without recording the change in Git, so the next apply fights your patch.

Practical tip: start with kubectl patch deployment my-app dash p and a small JSON snippet, or use dash dash type equals json with an RFC 6902 operations array when you need precision. Always kubectl get after to verify.

Rule to remember: patch for surgical updates - still put lasting changes in Git.
