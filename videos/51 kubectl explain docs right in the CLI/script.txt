Forgot a spec field and do not want to open a browser?

kubectl explain. It prints the API schema and field descriptions straight from the cluster's OpenAPI. kubectl explain deployment shows top-level fields. kubectl explain deployment dot spec dot template dot spec digs into the Pod template.

This is faster than searching docs when you are mid-manifest. You learn which fields exist, which are required, and what they mean - matching the exact API version your cluster speaks, not a blog post for an older release.

What beginners get wrong: typing the wrong path and assuming the field does not exist, or explaining a kind that is not installed. Also forgetting dash dash recursive when they want the full nested tree in one shot.

Practical tip: keep explain open in a second terminal while writing YAML. Pair it with kubectl api-resources to confirm short names and API groups first.

Rule to remember: explain is cluster-local docs - trust it over random snippets.
