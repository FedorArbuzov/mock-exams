How do you see what will change in the cluster before you apply?

kubectl diff. It compares your local manifest to the live object and prints a unified diff of what apply would change. You get a preview without mutating the cluster.

Use it as a safety gate. Before a production apply, run kubectl diff dash f manifest.yaml and read every red and green line. Unexpected deletions, image swaps, or replica jumps stand out immediately. In CI, fail the job if diff shows changes you did not expect.

What beginners get wrong: applying blind because the YAML looks familiar, then discovering a typo wiped a volume mount. Or ignoring that diff needs server-side support and proper RBAC - if it fails, fix permissions instead of skipping the check.

Practical tip: combine with dash dash server-side when your cluster uses server-side apply, and review namespace and name carefully so you are not diffing the wrong object.

Rule to remember: diff first, apply second - never fly blind into prod.
