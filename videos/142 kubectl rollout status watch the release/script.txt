How do I know if a release is still going or already broken?

In simple terms, the command shows current rollout state and progress.

Concretely, treat that as a testable rule: The command shows current rollout state and progress. When reality disagrees, trust cluster signals over the story in your head.

Keep a tiny trusted command set. Short commands survive stress and stay readable when shown large on a phone screen.

Know what each command proves: get is inventory, describe is why, logs are the app voice, rollout is release health.

Beginner trap: pasting flag encyclopedias you cannot explain.

For the video, huge text: kubectl rollout status deploy/web.

If someone asks tomorrow what this changes, answer with the rule: the command shows current rollout state and progress.
