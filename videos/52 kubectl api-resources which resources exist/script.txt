How do you know which object types this cluster supports?

kubectl api-resources. It lists every API resource the cluster exposes - names, short names, API groups, whether they are namespaced, and the Kind. That list is the menu of what you can get, describe, and apply.

Why it matters: clusters differ. One has Ingress, another uses Gateway. Operators add CustomResourceDefinitions you will never see in a tutorial. api-resources shows the truth for this cluster, right now.

What beginners get wrong: memorizing resource names from a course and failing when a short name differs, or missing CRDs entirely. Also confusing api-resources with api-versions - versions tell you group slash version strings, resources tell you what kinds you can query.

Practical tip: filter with dash dash namespaced equals true, or grep for ingress, or use dash o wide. Then kubectl get that resource name. Short names like deploy, svc, and cm come from this list.

Rule to remember: api-resources is the cluster's menu - check it before you guess.
