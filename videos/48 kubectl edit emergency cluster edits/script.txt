How do you quickly fix a resource during a prod incident?

kubectl edit. It opens the live object in your editor - usually via the EDITOR or KUBE_EDITOR environment variable. You change a field, save, and the API updates the cluster immediately. No separate YAML file required in that moment.

It is built for emergencies. Bump a replica count, fix a bad env var, tweak a probe timeout while users are waiting. Speed matters more than ceremony when the page is down.

What beginners get wrong: treating edit as the permanent source of truth. The next kubectl apply from Git can overwrite your hot-fix, or Git drifts from the cluster and nobody knows why. Also editing the wrong namespace or the wrong object under pressure.

Practical rule: edit to stop the bleeding, then immediately copy the change back into Git and open a pull request. If you cannot commit it tonight, leave a ticket with the exact field you changed.

Rule to remember: edit is for incidents - Git is for lasting truth.
