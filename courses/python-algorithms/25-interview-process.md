# 25. Процесс: коммуникация, edge cases, отладка

## Введение

Сильное решение без озвучивания мыслей — риск **no hire**. Структура 45 минут так же важна, как паттерн.

---

## Таймлайн 45 мин

| Мин | Действие |
|-----|----------|
| 0–3 | Повторить задачу своими словами |
| 3–8 | Примеры, edge cases, brute idea |
| 8–12 | Оптимальный подход + сложность |
| 12–30 | Код (сначала сигнатура, потом тело) |
| 30–38 | Тест: пример + edge |
| 38–45 | Оптимизация space / follow-up |

---

## Edge cases checklist

- `[]`, `[1]`, все одинаковые  
- Отрицательные числа  
- Дубликаты  
- `None` для tree/list head  
- Off-by-one в slices  

---

## Коммуникация

| Фраза | Зачем |
|-------|-------|
| «Сначала O(n²), улучшу до O(n) hash» | показывает рост |
| «Проверю пустой массив» | зрелость |
| «Здесь invariant: окно без повторов» | для интервьюера |

Молчание >2 мин — красный флаг; говорите, даже если ищете.

---

## Отладка без print-spam

1. Прогон примера из условия вручную  
2. Один `print` mid в BS  
3. Упростить до меньшего n  

На CoderPad — тест-кейс в комментарии.

---

## Когда застряли

1. Упростить (малый n brute)  
2. Другой паттерн из [04](04-pattern-recognition.md)  
3. Спросить hint — лучше, чем молчать 15 мин

## Python-стиль на доске

```python
def solve(nums: list[int]) -> int:
    if not nums:
        return 0
    ...
```

Имена: `left`, `right`, `prefix`, не `i,j,k` везде без смысла.
