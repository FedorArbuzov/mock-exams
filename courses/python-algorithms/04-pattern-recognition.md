# 04. Как узнавать паттерн задачи

## Введение

Первые **3–5 минут** — чтение условия и классификация. Ошибка: сразу кодить brute force без понимания, что это «sliding window».

---

## Decision tree (упрощённо)

```text
Массив/строка, подмассив/подстрока?
  ├─ сумма/произведение фиксировано → prefix / sliding window
  ├─ пары, палиндром, sorted → two pointers
  └─ частота, «есть ли» → hash map

Поиск в sorted / ответ монотонен → binary search

Дерево/граф → BFS/DFS

Оптимум «взять/не взять», счётчик путей → DP

Жадный выбор локально → greedy (доказать!)

Все перестановки/комбинации → backtracking
```

---

## Ключевые слова в условии

| Фраза | Паттерн |
|-------|---------|
| «подмассив максимальной суммы» | Kadane / prefix |
| «k подряд» | sliding window |
| «без повторов» в подстроке | window + set |
| «минимум отсортированного массива» | rotated BS |
| «связный компонент» | graph DFS/BFS |
| «минимум монет» | DP unbounded knapsack |

## Уточняющие вопросы (30 сек)

1. Размер n? Значения (отрицательные?)  
2. Пустой вход? Один элемент?  
3. Дубликаты? Sorted?  
4. Переполнение int? (редко в Python)  
5. In-place или новый массив?

---

## Brute → optimize

Допустимо сказать: «Сначала O(n²) все пары, потом улучшу до O(n) hash map» — и **сделать** улучшение.
