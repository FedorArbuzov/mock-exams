# 02. Сложность: Big-O, амортизация, мастер-теорема

## Введение

«O(n)» на интервью — не формальность. Интервьюер проверяет, видите ли вы **лишний вложенный цикл** и **рост памяти** до написания кода.

---

## Asymptotic notation

| Обозначение | Смысл |
|-------------|-------|
| O(f) | верхняя граница (worst case обычно) |
| Ω(f) | нижняя |
| Θ(f) | tight bound |

На практике говорят «O(n)» = «линейно по n».

---

## Типичные сложности

| Сложность | Пример n=10⁵ |
|-----------|--------------|
| O(1) | hash lookup |
| O(log n) | binary search |
| O(n) | один проход |
| O(n log n) | sort |
| O(n²) | вложенные циклы по n |
| O(2ⁿ) | brute subset без DP |
| O(n!) | перестановки brute |

**Правило:** n ≤ 10⁶ → O(n) или O(n log n) ок; O(n²) — риск TLE.

---

## Анализ кода

```python
def f(nums: list[int]) -> int:
    s = set(nums)          # O(n)
    for x in nums:         # O(n)
        if x + 1 in s:     # O(1) avg
            ...
    return 0
# Time O(n), Space O(n)
```

Вложенность:

```python
for i in range(n):
    for j in range(i, n):  # O(n²)
        ...
```

---

## Амортизация

`list.append` — амортизированный O(1): редкое удвоение массива.

`dict`/`set` — O(1) среднее, O(n) worst (редко на интервью).

---

## Рекурсия

```python
def dfs(node):
    if not node:
        return 0
    return 1 + dfs(node.left) + dfs(node.right)
```

Дерево: время O(n), стек вызовов **O(h)** высоты (O(n) worst skewed).

---

## Мастер-теорема (для divide & conquer)

`T(n) = aT(n/b) + O(n^d)` — для merge sort: a=2, b=2, d=1 → O(n log n).

На интервью достаточно **интуиции**: делим пополам → +log n уровней.
