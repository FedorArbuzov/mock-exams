# 05. test, [[ ]], case

## Введение: «if [ $var = prod ]» и пустой $var

Классическая ошибка: переменная пустая, условие **`[ $var = prod ]`** превращается в **`[ = prod ]`** — syntax error или неожиданное совпадение. В bash-скриптах DevOps условия — основа ветвления deploy, проверки конфигов и валидации аргументов.

## Что вы узнаете

- **`[[ ]]`** vs **`[ ]`** (test).
- Проверки файлов, строк, чисел.
- **`case`** для ENV и режимов.
- **`(( ))`** для арифметики.
- **`if/elif/else`** с командами systemd/curl.

---

## Два синтаксиса

| | `[ ... ]` | `[[ ... ]]` |
|---|-----------|-------------|
| Shell | POSIX test | bash |
| Строки | меньше возможностей | `==`, regex `=~`, `&&` внутри |
| Рекомендация | sh-совместимость | **новые bash-скрипты** |

**Всегда** кавычки: `"$var"`.

---

## Файлы и каталоги

```bash
[[ -f /etc/passwd ]]      # обычный файл
[[ -d /var/log ]]         # каталог
[[ -e /tmp/maybe ]]       # существует
[[ -r /etc/shadow ]]      # читаем
[[ -x /usr/bin/curl ]]    # исполняемый
[[ -s file.txt ]]         # размер > 0
[[ -L /path ]]            # symlink
```

---

## Строки

```bash
[[ -z "$var" ]]            # пустая
[[ -n "$var" ]]            # не пустая
[[ "$a" == "$b" ]]
[[ "$file" == *.log ]]     # glob в bash [[ ]]
[[ "$ver" =~ ^[0-9]+\.[0-9]+$ ]]   # regex
```

---

## Числа

```bash
[[ $count -gt 10 ]]
[[ $a -eq $b ]]
```

| Оператор | Значение |
|----------|----------|
| `-eq`, `-ne` | равно / не равно |
| `-lt`, `-le`, `-gt`, `-ge` | сравнение |

Арифметика:

```bash
(( count > 10 )) && echo big
(( count++ ))
```

---

## Логика внутри [[ ]]

```bash
if [[ -f "$f" && -r "$f" ]]; then
  cat "$f"
fi

[[ -z "$x" || "$x" == "default" ]]
```

## case — ветвление по значению

```bash
ENV=${1:-dev}

case "$ENV" in
  prod|production)
    REPLICAS=5
    URL="https://api.example.com"
    ;;
  stage|staging)
    REPLICAS=2
    URL="https://stage.example.com"
    ;;
  dev|development|"")
    REPLICAS=1
    URL="http://localhost:8080"
    ;;
  *)
    echo "Unknown ENV: $ENV" >&2
    exit 1
    ;;
esac
```

| Паттерн | Смысл |
|---------|--------|
| `a\|b` | a или b |
| `*` | любая строка |
| `?)` | один символ |
| `*)` | default — **обязателен** для безопасности |

## if с командами

```bash
if systemctl is-active --quiet nginx; then
  echo "nginx running"
elif systemctl is-enabled --quiet nginx 2>/dev/null; then
  echo "enabled but stopped"
else
  echo "not configured"
fi

if curl -sf http://127.0.0.1/ >/dev/null; then
  echo "http ok"
fi
```

С **`set -e`**: условие в `if` **не** триггерит errexit при false.

---

## Типичные ошибки

| Ошибка | Исправление |
|--------|-------------|
| `[ $a = $b ]` без кавычек | `[[ "$a" == "$b" ]]` |
| `=` вместо `==` в [[ ]] | `==` для строк |
| забыли `*)` в case | неизвестные ENV проходят молча |
| сравнение чисел как строк | `-eq` или `(( ))` |

---

## В продакшене

Валидация ENV/REGION в начале скрипта — `case` + exit 1. Не смешивайте **отдельные** `if` для взаимоисключающих режимов — один `case` читабельнее.

---

## Резюме

**`[[ ]]`** — основной инструмент условий в bash. **`case`** — для режимов deploy. Кавычки и **default `*)`** обязательны.
