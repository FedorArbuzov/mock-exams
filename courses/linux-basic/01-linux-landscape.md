# 01. Дистрибутивы, FHS, документация

## Что такое «Linux» на самом деле

Когда коллега говорит «у нас на сервере Linux», чаще всего имеется в виду **дистрибутив** — готовый набор: ядро, системные утилиты, пакетный менеджер, политики безопасности и дефолтные сервисы.

**Linux** в узком смысле — только **ядро**: планировщик, память, сеть, драйверы. Ядро одно, а «Ubuntu» и «Rocky Linux» — разные **дистрибутивы** поверх него. Для DevOps это важно: в CI образ `ubuntu:24.04`, в Kubernetes ноды могут быть Container-Optimized OS или RHEL, в legacy — CentOS 7. Команды в целом одинаковые, но пути к конфигам, имена сервисов и пакетный менеджер отличаются.

В нашем стенде — **Ubuntu 24.04 LTS** (Long Term Support): предсказуемые обновления безопасности несколько лет, огромная документация, привычный `apt`.

| Семейство | Примеры | Пакеты | Где встречается |
|-----------|---------|--------|------------------|
| Debian | Ubuntu, Debian | `apt`, `dpkg` | Облако, контейнеры, стартапы |
| RHEL | Rocky, Alma, RHEL | `dnf`, `rpm` | Enterprise, банки, вендоры |

Если вы привыкли к Ubuntu, на RHEL те же идеи (systemd, `/etc`, пользователи), но вместо `apt install nginx` будет `dnf install nginx`, а группа sudo часто называется **wheel**.

## FHS — «где что лежит»

**FHS** (Filesystem Hierarchy Standard) — договорённость, чтобы любой админ не искал конфиг nginx в `/tmp`. В проде вы постоянно делаете `cd /etc/...`, смотрите логи в `/var/log`, данные приложения — в `/var/lib`.

| Путь | Назначение | Пример для DevOps |
|------|------------|-------------------|
| `/` | Корень всей ФС | `df -h /` при «диск забит» |
| `/etc` | Конфигурация | `sshd_config`, unit systemd |
| `/var` | Меняющиеся данные | логи, очереди, БД |
| `/var/log` | Логи | `journalctl`, nginx access.log |
| `/home` | Домашние каталоги | ключи SSH, dotfiles |
| `/tmp` | Временное | часто очищается; не хранить важное |
| `/usr/bin` | Программы из пакетов | `python3`, `curl` |
| `/proc`, `/sys` | Интерфейс к ядру | `cat /proc/cpuinfo` |
| `/dev` | Устройства | диски, pseudo-terminals |
| `/root` | Home суперпользователя | только для root |

**Практическое правило:** конфиги правим в `/etc`, состояние сервиса смотрим через systemd и `/var/log`, бинарники не копируем вручную в `/usr/bin` — ставим пакетом.

Типичный вопрос на собеседовании: «где лежит конфиг nginx?» — на Ubuntu после `apt install nginx` это `/etc/nginx/nginx.conf`, сайты — `/etc/nginx/sites-enabled/`.

## Кто вы в системе

Первые команды в любой новой среде:

```bash
whoami
id
echo $SHELL
echo $HOME
hostname
```

`whoami` — текущий логин. `id` — UID, основная группа и **все** группы (важно для sudo и docker). `$SHELL` — оболочка по умолчанию; в курсе это **bash** (`/bin/bash`).

## Документация под рукой — man и не только

На сервере без интернета **man** — ваш друг. Не нужно гуглить синтаксис `tar`, если есть `man tar`.

```bash
man ls
man 5 passwd      # секция 5 = форматы файлов, не команды
man -k password   # поиск по ключевым словам в описаниях
```

Секции man, которые реально нужны админу:

| Секция | Содержимое | Пример |
|--------|------------|--------|
| 1 | Пользовательские команды | `man systemctl` |
| 5 | Форматы конфигов | `man 5 crontab` |
| 8 | Администрирование | `man 8 mount` |

Встроенные команды bash (`cd`, `export`) не имеют бинарника в `/usr/bin` — для них:

```bash
help cd
```

Краткая справка по флагу:

```bash
ls --help | less
apropos mount
whatis systemd
```

Привычка: перед экспериментом с незнакомым флагом — `man` или `--help`, а не угадывание.

## Версия и «что за машина»

```bash
cat /etc/os-release
uname -r
uname -a
```

`/etc/os-release` — человекочитаемое имя дистрибутива. `uname -r` — версия **ядра** (важно при багах драйверов или eBPF). В тикете в поддержку обычно прикладывают оба вывода.
