# 09. Процессы, сигналы, nice

## Процесс — не «программа в списке», а живой объект

Запущенный `nginx` — это не один PID навсегда: master и workers, перезапуски, дочерние процессы. У каждого процесса есть **PID**, родитель **PPID**, пользователь (от чьего имени работает), открытые файлы и сокеты.

```bash
ps aux
ps -ef
ps -ef --forest | head -40
```

| ps aux | Значение |
|--------|----------|
| USER | от чьего UID идут права |
| PID | идентификатор |
| %CPU / %MEM | текущая нагрузка |
| STAT | R run, S sleep, Z zombie, D uninterruptible I/O |
| COMMAND | argv |

В инциденте «сервер тормозит» вы смотрите `%CPU`, `%MEM`, STAT и дерево — не убиваете вслепую.

## PID 1 — «прародитель»

```bash
ps -p 1 -o pid,cmd
```

На сервере это **systemd**. В Docker-контейнере тоже часто systemd или tini. Процессы-сироты «усыновляет» PID 1 — поэтому зомби иногда копятся, если родитель не делает `wait()`.

## Сигналы — вежливая и грубая остановка

| Сигнал | № | Когда |
|--------|---|--------|
| SIGHUP | 1 | перечитать конфиг (nginx, sshd) |
| SIGINT | 2 | Ctrl+C в терминале |
| SIGTERM | 15 | корректное завершение (`kill PID`) |
| SIGKILL | 9 | убить немедленно, процесс не ловит |

```bash
kill PID
kill -15 PID
kill -9 PID        # только если TERM не помог
pkill -f "pattern"
```

**Порядок в проде:** `systemctl stop` → подождать → если завис — разбор, потом `-9`. SIGKILL не даёт приложению закрыть соединения и сбросить state.

## Фон в текущем shell

```bash
sleep 120 &
jobs -l
fg %1
# Ctrl+Z — приостановить; bg %1 — продолжить в фоне
```

В SSH-сессии фоновые jobs привязаны к терминалу; для долгих задач — `screen`, `tmux` или systemd service.

## nice — приоритет CPU, не «магия»

Nice от **-20** (выше приоритет, обычно только root) до **19** (ниже). Обычный пользователь может только **увеличивать** nice (отдавать CPU другим).

```bash
nice -n 10 stress-ng --cpu 1 --timeout 30s &
ps -o pid,ni,cmd -p $!
sudo renice -n -5 -p PID   # root может понизить nice
```

Batch-задачи (бэкап, отчёт) часто запускают с `nice 10`, чтобы не душить API.

## top и htop

```bash
top    # M — по памяти, P — по CPU, q — выход
htop   # если установлен
```

Load average (1/5/15) — **очередь** runnable процессов. Высокий load при низком CPU часто значит **ожидание диска** (iowait) — смотрите `iostat`, не только top.

## Zombie (STAT Z)

Процесс завершился, но слот в таблице остался, пока родитель не прочитал exit code. Пара зомби — не страшно; сотни — ищите баг в родителе или скрипте, который spawn без wait.
