# 15. tar, gzip, rsync

## Архивы — не «сжатие ради сжатия»

**tar** упаковывает дерево файлов в один поток (сохраняет имена, права, иногда владельца). Сжатие — отдельно: **gzip**, **xz**. Так делают бэкапы конфигов, перенос артефактов, отправку в S3 «как один файл».

```bash
tar -cvf archive.tar /etc/nginx
tar -czvf archive.tar.gz /etc/nginx
tar -tzvf archive.tar.gz
tar -xzvf archive.tar.gz -C /tmp/restore/
```

| Ключ | Значение |
|------|----------|
| `-c` | создать |
| `-x` | распаковать |
| `-t` | список содержимого |
| `-v` | подробно |
| `-f` | имя файла (обязателен) |
| `-z` | gzip |
| `-J` | xz (сильнее сжимает, дольше) |

Исключения:

```bash
tar -czvf backup.tar.gz --exclude='*.log' /var/www
```

**Осторожно:** `tar -czf backup.tar.gz /` с корня — классическая ошибка; всегда указывайте нужные каталоги.

## gzip / xz отдельно

```bash
gzip big.log           # → big.log.gz, исходник удаляется
zcat big.log.gz | head
```

## rsync — когда cp и scp мало

**rsync** передаёт **изменения** (delta), сохраняет права с `-a`, умеет SSH.

```bash
rsync -av /local/dir/ user@host:/remote/dir/
rsync -av --delete /src/ /dst/    # зеркало: лишнее на dst удалится
rsync -avz -e ssh /data/ course@172.28.0.11:/backup/
```

| Ключ | Эффект |
|------|--------|
| `-a` | archive: рекурсия, права, время |
| `-v` | список файлов |
| `-z` | сжатие при передаче |
| `--delete` | удалить на приёмнике то, чего нет в источнике |

**Слэш в конце важен:**

- `src/` — содержимое каталога
- `src` — каталог целиком как один уровень

`rsync --delete` на прод без `--dry-run` — способ случайно стереть бэкап. Сначала:

```bash
rsync -av --delete --dry-run /src/ /dst/
```

## Что выбрать

| Задача | Инструмент |
|--------|------------|
| Разовая копия на том же диске | cp |
| Бэкап конфигов + сжатие | tar.gz |
| Синхронизация серверов | rsync over ssh |
| Облачный offsite | tar + upload (rclone, aws cli) |
