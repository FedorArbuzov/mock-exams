# 02. Shell, PATH, перенаправление, pipe

## Зачем это DevOps-инженеру

Половина рабочего дня в терминале — **цепочки команд**: вытащить IP из вывода, отфильтровать лог, отправить stderr в файл, проверить, что в pipe ничего не потерялось. CI/CD, Ansible и kubectl — тоже «оболочки» вокруг тех же идей: stdout/stderr, код возврата, переменные окружения.

Этот урок про **bash** в интерактивном режиме. Скрипты (строгий режим, функции, отладка) — в курсе [`linux-shell`](../linux-shell/README.md).

## Интерактивный shell: кто выполняет команду

Когда вы набираете `ls`, работает не «Linux», а **shell** — программа-интерпретатор. Shell читает строку, разбивает на слова, ищет программу, запускает, показывает вывод.

```bash
echo $0          # имя текущей оболочки, обычно -bash или bash
type cd          # cd is a shell builtin
type ls          # ls is /usr/bin/ls
```

**Встроенные** команды (`cd`, `export`, `source`, `alias`) выполняет сам bash — отдельного файла нет. **Внешние** — обычные бинарники; bash ищет их в каталогах из переменной **PATH**.

Если `cd` не работает в скрипте, запущенном как `./script.sh` — часто забыли, что `cd` влияет только на **текущий** shell-процесс, а не на родителя.

## PATH — где bash ищет программы

```bash
echo $PATH
# типично: /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

which nginx
type -a python3
command -v docker
```

Если видите `command not found` — либо пакет не установлен, либо бинарник лежит вне PATH (например `/opt/myapp/bin`).

Временно добавить каталог **в начало** PATH (чтобы «перебить» системную версию):

```bash
export PATH="/opt/myapp/bin:$PATH"
```

Постоянно — строка в `~/.bashrc` или файл в `/etc/profile.d/` (для всех пользователей). После правки: `source ~/.bashrc` или новый login.

**Ошибка новичка:** писать `PATH=...` без `export` — переменная видна только текущему shell, дочерние процессы (и cron) её не увидят.

## Три потока: stdin, stdout, stderr

У каждого процесса по умолчанию:

| Дескриптор | Имя | Куда идёт в терминале |
|------------|-----|------------------------|
| 0 | stdin | с клавиатуры |
| 1 | stdout | на экран |
| 2 | stderr | на экран (отдельный поток!) |

Ошибки часто идут в **stderr**, чтобы их можно было отделить от нормального вывода. Пример: `ls` успешно печатает каталоги в stdout, а «Permission denied» — в stderr.

| Конструкция | Эффект |
|-------------|--------|
| `cmd > file` | stdout в файл (перезапись) |
| `cmd >> file` | stdout дописать в конец |
| `cmd 2> file` | только stderr в файл |
| `cmd &> file` | stdout и stderr в один файл (bash) |
| `cmd > file 2>&1` | stderr «привязать» к stdout (классика в скриптах) |
| `cmd < file` | stdin из файла |

Пример разделения потоков:

```bash
ls /etc /root > /tmp/ok.txt 2> /tmp/err.txt
wc -l /tmp/ok.txt
cat /tmp/err.txt
```

Вы увидите длинный список `/etc` в `ok.txt` и сообщения об отказе для `/root` в `err.txt`.

## Pipe — конвейер

```bash
ss -tlnp 2>/dev/null | head -20
ps aux | grep -E 'ssh|nginx' | grep -v grep
```

Выход **слева** становится входом **справа**. Каждая стадия — отдельный процесс; это удобно для «сырого» вывода → фильтр → подсчёт.

**Нюанс:** код возврата всего pipe в bash по умолчанию — код **последней** команды. Если нужно знать, упала ли первая:

```bash
set -o pipefail    # в скриптах — обязательно
# или разово:
grep foo /etc/hosts | wc -l
echo "${PIPESTATUS[@]}"
```

В интерактиве для отладки «почему пусто» иногда полезно убрать pipe и смотреть левую команду отдельно.

## Glob — подстановка имён файлов

```bash
echo *.service
ls /var/log/syslog*
```

Shell **до** запуска команды разворачивает шаблон в список имён. Если совпадений нет, в bash шаблон может остаться буквально `*.log` — и команда скажет «No such file». В скриптах включают `shopt -s nullglob`, чтобы пустой список не ломал цикл.

Кавычки отключают glob: `echo "*.log"` напечатает звёздочку буквально.

## Переменные окружения

```bash
NAME=lab
echo "Hello $NAME"
echo "${HOME}/bin"
export DB_HOST=127.0.0.1
env | grep DB_
```

Без **export** переменная видна только текущему shell. С **export** — наследуется дочерними процессами (`nginx`, `python`, job в CI).

Подстановка `${VAR:-default}` — если VAR пустая, подставить default (удобно в скриптах деплоя).

## Горячие клавиши и история

| Комбинация | Действие |
|------------|----------|
| Ctrl+C | прервать текущую команду |
| Ctrl+D | конец ввода (выйти из shell, если строка пустая) |
| Ctrl+L | очистить экран |
| ↑ / ↓ | листать историю |

```bash
history | tail -20
!42        # повторить команду №42 из history
!!         # повторить предыдущую
```

На jump-хостах с включённым `HISTSIZE` история — рабочий журнал: «что я делал перед инцидентом».

## Типичные ошибки

- Путать `>` и `>>` — случайно затереть лог при повторном запуске.
- Забыть `2>&1` в cron и получить пустой лог-файл при ошибках только в stderr.
- Делать `grep` в pipe без подавления своего stderr (`2>/dev/null`), когда ищете в `/etc` без прав.
