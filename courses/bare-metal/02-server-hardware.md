# 02. Серверное железо

## Форм-факторы

| Форм | Высота | Где |
|---|---|---|
| **1U / 2U** | 1–2 юнита в стойке | стандарт ЦОД |
| **Blade** | в шасси | плотные кластеры |
| **Tower** | напольный | офис, малые ЦОД |

**U (unit)** — 44.45 мм высоты в 19" стойке.

## CPU и память

- **Sockets** — сколько физических процессоров.
- **Cores / threads** — для Kubernetes `allocatable cpu` на ноде ≈ физические потоки минус system reserved.
- **NUMA** — на больших серверах память привязана к socket; неправильная affinity бьёт по latency (важно для БД и HPC).
- **ECC RAM** — исправление битовых ошибок; в серверах — норма.

## Диски

| Тип | Когда |
|---|---|
| **HDD** | большие объёмы, cold data |
| **SATA/SAS SSD** | boot, общее хранилище |
| **NVMe U.2 / M.2** | максимальный IOPS, локальные тома для etcd, DB |

**Hot-swap** — замена диска без выключения (при поддержке backplane и RAID).

## RAID-контроллер

Аппаратный RAID на карте Perc/HPE Smart Array:

- RAID1 — зеркало boot.
- RAID10 — БД.
- RAID5/6 — ёмко, но rebuild долгий.

**JBOD / HBA mode** — диски видны ОС напрямую; RAID делает **mdadm** или **Ceph** — типично для cloud-native storage.

## Сеть на материнской плате

- 2× **1G/10G/25G** RJ45 или SFP+.
- Отдельный порт **BMC** (management) — см. урок 03.

## Спецификация (how to read)

Пример: *2U, 2× Intel Xeon Silver 32C, 256GB RAM, 4×1.92TB NVMe, 2×10GbE, iDRAC9*.

DevOps не обязан подбирать железо с нуля, но должен **читать** spec и понимать узкие места.
