# 02. HTTP: методы, коды, safe и idempotent

## Введение

Клиент повторил запрос после таймаута. Сервер вернул `200` с телом «ошибка: нет stock». Это не «мелочь HTTP» — это **контракт**, который ломает интеграции и retry-логику SDK.

---

## Методы HTTP

| Метод | Safe | Idempotent | Типичное использование |
|-------|------|------------|------------------------|
| **GET** | да | да | чтение, списки |
| **HEAD** | да | да | метаданные без тела |
| **PUT** | нет | да | полная замена ресурса по URL |
| **PATCH** | нет | * | частичное обновление |
| **POST** | нет | нет | создание, действия, поиск (осторожно) |
| **DELETE** | нет | да | удаление |

\* PATCH идемпотентен **если** семантика «замени поле X на Y», не «добавь 1 к счётчику».

```text
Safe       = не меняет состояние на сервере (GET не должен списывать деньги)
Idempotent = повтор даёт тот же эффект, что один вызов
```

---

## Выбор метода для операций

| Операция | Метод | URL |
|----------|-------|-----|
| Список заказов | GET | `/orders` |
| Один заказ | GET | `/orders/{id}` |
| Создать заказ | POST | `/orders` |
| Заменить заказ целиком | PUT | `/orders/{id}` |
| Обновить статус | PATCH | `/orders/{id}` |
| Удалить | DELETE | `/orders/{id}` |
| Отменить (действие) | POST | `/orders/{id}/cancel` **или** PATCH `status=cancelled` |

**Два стиля отмены:** sub-resource `POST .../cancel` (явное действие) vs PATCH поля `status` (ресурсная модель). Выберите один и документируйте.

---

## Коды статуса — минимальный набор

| Код | Когда |
|-----|-------|
| **200** | OK с телом (GET, PATCH, PUT) |
| **201** | Created; заголовок `Location: /orders/42` |
| **204** | OK без тела (DELETE, иногда PATCH) |
| **304** | Not Modified (кэш ETag) |
| **400** | Синтаксис/семантика запроса (клиент исправим) |
| **401** | Не аутентифицирован |
| **403** | Аутентифицирован, но нет прав |
| **404** | Ресурс не найден **или** скрыт от чужих (осторожно с утечкой) |
| **409** | Конфликт (дубликат, версия, state machine) |
| **422** | Валидация полей (часто в JSON API; в чистом REST спорят с 400) |
| **429** | Rate limit |
| **500** | Неожиданная ошибка сервера |
| **502/503/504** | Прокси/upstream/таймаут — клиент **может** retry |

**Антипаттерн:** всегда `200` + `{ "success": false }` — ломает мониторинг, кэш и HTTP-клиенты.

---

## GET с побочными эффектами

```http
GET /orders/42/charge?amount=100   # НЕЛЬЗЯ
POST /orders/42/charges            # правильно
```

Прокси и CDN **кэшируют GET**. Повтор по ссылке из лога не должен списывать деньги.

## Content negotiation (кратко)

| Заголовок | Зачем |
|-----------|-------|
| `Accept: application/json` | формат ответа |
| `Content-Type: application/json` | формат тела запроса |
| `Accept-Language` | локализация сообщений (редко в machine-to-machine) |
| `If-None-Match` / `ETag` | условный GET, экономия трафика |

Версионирование через `Accept` — [07-versioning-compatibility](07-versioning-compatibility.md).

## Идемпотентность на уровне HTTP vs приложения

HTTP DELETE идемпотентен: второй DELETE → 404 или 204 — **эффект** «ресурса нет».

POST **не** идемпотентен без **Idempotency-Key** — [08-idempotency-retries](08-idempotency-retries.md).

## Резюме

Метод и код статуса — часть **публичного контракта**. Safe/idempotent определяют, **можно ли retry**. Не прячьте ошибки в `200`.
