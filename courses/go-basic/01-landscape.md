# 01. Ландшафт: компиляция и экосистема Go

## Что вы узнаете

- Краткую **историю Go** и дизайн-цели языка.
- Цепочку: исходник `.go` → **компилятор** → бинарник → **runtime** (GC, scheduler).
- Что такое **компилируемый** язык на практике.
- Что такое **сборщик мусора** и почему в Go нет `free()`.
- Обзор **goroutines** (без углубления — полноценно они разбираются в отдельном курсе по concurrency).

## История и дизайн Go

**Go** (Golang) — язык с открытым исходным кодом, анонсированный Google в **2009**, стабильная версия **1.0** в 2012. Авторы — Роб Пайк, Кен Томпсон, Роберт Грисемер — хотели язык для **инфраструктурного** кода: компиляция секунды, читаемость, встроенная concurrency.

| Цель | Как проявляется в языке |
|------|-------------------------|
| Быстрая сборка | Маленький компилятор, кэш в `go build` |
| Простой синтаксис | Мало ключевых слов, нет наследования классов |
| Явная обработка ошибок | `if err != nil`, не exceptions по умолчанию |
| Concurrency | goroutines + channels в стандартной библиотеке |
| Статическая типизация | Ошибки типов на этапе компиляции |

## От исходника до выполнения

```text
Исходный код (.go файлы, пакеты)
        │
        ▼
   go build / go run
        │
        ▼
   Компилятор gc (machine code или archive)
        │
        ▼
   Исполняемый файл + runtime Go
        │
        ├── GC (сборка мусора)
        ├── Scheduler (GMP: goroutines на OS threads)
        └── Стандартная библиотека (net, fmt, …)
```

```go
package main

import "fmt"

func main() {
	fmt.Println("Compiled once, runs anywhere (same OS/arch)")
}
```

`go run` компилирует во временный бинарник и сразу запускает. `go build -o app ./cmd/app` — готовый артефакт для деплоя.

## Компилируемый язык

Программа компилируется в машинный код **до** запуска — интерпретатор на целевой машине не нужен:

```bash
go build -o reindex ./cmd/reindex
./reindex    # интерпретатор Go не нужен на целевой машине
```

Практические следствия:

- предсказуемый бинарник, быстрый cold start;
- ошибки типов ловятся **до** деплоя, а не в runtime;
- cross-compile: `GOOS=linux GOARCH=amd64 go build` с любой машины.

Минус — нет встроенной интерактивной консоли уровня REPL; вместо неё на практике используют короткие `go run` однофайловых сниппетов ([03-lab-first-programs.md](03-lab-first-programs.md)).

## Статическая типизация

Тип переменной известен компилятору:

```go
var price float64 = 79.99
// price = "free"  // compile error: cannot use "free" (untyped string) as float64
```

Несовместимость типов — это **ошибка компиляции**, а не сюрприз в продакшене.

## Сборщик мусора (GC)

В Go память под `new`, `make`, литералы выделяется в **heap**; **GC** освобождает недостижимые объекты. Программист **не** вызывает `free` и не считает reference counting вручную.

```go
func buildCart() []string {
	items := make([]string, 0, 10) // slice на heap
	items = append(items, "keyboard")
	return items // GC позже уберёт, если никто не ссылается
}
```

Практические следствия:

- не нужно pairing `malloc`/`free`;
- latency spikes при паузах GC — тема профилирования на более продвинутом уровне;
- **не** злоупотребляйте указателями «для скорости» без измерений ([11-pointers.md](11-pointers.md)).

## Goroutines: preview

**Goroutine** — легковесный поток выполнения, стартует с ключевого слова `go`:

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	go func() {
		fmt.Println("from goroutine")
	}()
	fmt.Println("from main")
	time.Sleep(100 * time.Millisecond) // костыль для демо; позже — sync, channels
}
```

Порядок строк **не гарантирован** без синхронизации. На этом курсе goroutines только **называем**, не строим production patterns — синхронизация и каналы — тема отдельного продвинутого курса.

## Типичные ошибки

**«Go интерпретируемый».** `go run` всё равно компилирует; просто не оставляет бинарник по умолчанию.

**Ждать ООП с классами и наследованием.** В Go — **structs** и **composition** ([07-structs.md](07-structs.md)), не class hierarchy.

**Сравнивать goroutine с OS thread 1:1.** Goroutines дешевле; тысячи goroutines — норма, тысячи потоков ОС — нет.

**Игнорировать `if err != nil` «пока учусь».** Обработка ошибок — идиома с первого дня ([21-errors.md](21-errors.md)), не «потом в проде».

**Путать `go` keyword с `go mod`.** `go func()` — goroutine; `go get` — модуль зависимостей.

## Резюме

Go — **статически типизируемый компилируемый** язык с **GC** и встроенной моделью **concurrency** (goroutines). Исходник превращается в бинарник с runtime; деплой проще, чем у интерпретируемых стеков. Следующий шаг — переменные и zero values, где статическая типизация ощущается в каждой строке.
