# 02. Переменные: `var`, `:=`, zero values, именование

## Что вы узнаете

- Объявление через **`var`** и короткое **`:=`** — когда что использовать.
- **Zero values** для всех базовых типов.
- **Блочную область видимости**.
- Правила **именования** (exported vs unexported — preview).
- Почему неиспользуемые переменные — **ошибка компиляции**.

## Два способа объявить переменную

```go
package main

import "fmt"

func main() {
	var name string = "Ann"
	var age int           // zero value: 0
	count := 3            // short declaration, тип выводится как int
	price := 79.99        // float64

	fmt.Println(name, age, count, price)
}
```

| Способ | Синтаксис | Когда использовать |
|--------|-----------|-------------------|
| `var` | `var x int` или `var x int = 5` | поля struct, package level, явный тип, zero value осознанно |
| `:=` | `x := 5` | локальные переменные в функциях, тип выводится |
| `:=` в `if` | `if v := f(); v > 0` | короткий scope для временной переменной |

**Правило курса:** внутри `func` по умолчанию **`:=`**. **`var`** — когда нужен тип без инициализации, несколько переменных в одном блоке, или объявление на уровне пакета.

```go
var (
	Debug   bool   = false
	APIBase string = "http://localhost:8090"
)
```

В Go нет hoisting: переменная существует только **после** строки объявления, в пределах своего блока.

## Zero values — «по умолчанию всё заполнено»

В Go каждый тип имеет **zero value**. Переменная без явной инициализации получает точное значение по умолчанию, а не остаётся неопределённой:

```go
var i int
var f float64
var b bool
var s string
var p *int

fmt.Println(i, f, b, s, p)
// 0 0 false  <nil>
```

| Тип | Zero value |
|-----|------------|
| `int`, `int64`, … | `0` |
| `float64` | `0` |
| `bool` | `false` |
| `string` | `""` (пустая строка, не nil) |
| pointer, slice, map, chan, func, interface | `nil` |

Практический кейс: структура заказа после `json.Unmarshal`:

```go
type Order struct {
	ID       int     `json:"id"`
	Total    float64 `json:"total"`
	Discount float64 `json:"discount"` // если ключа нет в JSON → 0, не «отсутствует»
}
```

Если нужно различать «поле не задано» и «поле равно нулю», позже используют указатели (`*float64`) или nullable-типы — эта тема раскрывается в главе про указатели.

## Короткое объявление `:=`

Работает **только внутри функций** (не на уровне пакета):

```go
func example() {
	sku := "KB-1"
	qty := 2
	sku, line := sku, sku+qty // хотя бы одна новая переменная справа
	_ = line
}
```

**`:=` требует хотя бы одной новой переменной** слева:

```go
x := 10
x, y := 20, 30 // OK: y новая
// x := 40      // ошибка: no new variables on left side of :=
```

Тип выводится из правой части:

```go
n := 42        // int
pi := 3.14     // float64
ok := true     // bool
msg := "hi"    // string
```

Явный тип при `var`:

```go
var userID int64 = 9007199254740993
```

## Область видимости: блоки

```go
func process() {
	discount := 0.1
	if discount > 0 {
		label := "sale"
		fmt.Println(label)
	}
	// fmt.Println(label) // undefined: label
}
```

`if`, `for`, `switch`, `{ }` — отдельные блоки. Переменная из `:=` в `if init` видна **только внутри** `if`:

```go
if err := save(); err != nil {
	return err
}
// err недоступен
```

Это намеренно ограничивает область видимости временных имён до необходимого блока.

### `for` и переменная цикла

```go
for i := 0; i < 3; i++ {
	go func() {
		fmt.Println(i) // до Go 1.22 — классическая ловушка с общей переменной
	}()
}
```

В Go 1.22+ переменная `i` в `for` — **новая на каждой итерации**. На более старых версиях для того же результата нужно было явно копировать: `i := i` внутри тела цикла.

## Именование

- **CamelCase** для имён: `orderID`, `fullName`.
- Первая буква **заглавная** — экспорт (видимость из других пакетов): `type Product struct`, поле `Title string`.
- Строчная — только внутри пакета: `func parseSKU()`.
- Аббревиатуры: `HTTPClient`, `userID` (не `UserId`).
- Короткие имена в маленьком scope: `i`, `err`; длинные в API: `customerEmail`.

```go
type Product struct {
	ID    int64   // exported field
	title string  // unexported — только этот пакет
}
```

## Неиспользуемые переменные и импорты

Компилятор **строгий**:

```go
func broken() {
	x := 1
	// x не используется → compile error: x declared and not used
}
```

Обход только осознанный — blank identifier `_`:

```go
_ = x // или _, err := f() когда err не нужен (редко)
```

То же для импортов: неиспользуемый `"fmt"` — ошибка компиляции, а не предупреждение линтера. `goimports` убирает лишнее при сохранении файла.

## `var` vs `:=`: практические сценарии

**Явный zero value перед ветвлением:**

```go
var err error
if condition {
	err = step1()
} else {
	err = step2()
}
if err != nil {
	return err
}
```

**Несколько переменных одного типа:**

```go
var width, height int = 100, 50
a, b := 1, 2
```

**Переобъявление в том же блоке (редко):**

```go
x := 1
if true {
	x, y := 2, 3 // новый x в inner block shadowing outer
	_ = x
}
```

Shadowing вне inner block легко путает — на code review часто просят переименовать.

## Типичные ошибки

**Использовать `:=` на уровне пакета.** Только `var` вне функций.

**Путать zero value с «ошибкой».** `if s == ""` — нормальная проверка пустой строки; не ждите специального «неопределённого» состояния.

**Забыть, что `false` и `0` — валидные данные.** `if count` не скомпилируется — в Go нет truthy/falsy; пишите `if count > 0`.

**Объявлять `err` дважды в одном блоке.** `err :=` и потом `err :=` — используйте `err =` для присваивания.

**Смешивать `var` и `:=` без причины.** Один стиль на файл: короткие локальные `:=`, осознанный `var`.

## Резюме

Переменные в Go объявляют через **`var`** или **`:=`**; без инициализации они получают **zero value**, а не «пустоту». Блочная область видимости и строгий компилятор отсекают мёртвый код до merge. Это фундамент для structs, JSON и ошибок — каждый следующий урок опирается на то, что `0`, `""` и `nil` имеют точный смысл.
