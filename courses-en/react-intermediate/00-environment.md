# 00. Environment: extending the project, MSW, dependencies

## Intro: "react-basic is done — what's next?"

It's Friday, the react-basic capstone demo just wrapped. The tech lead opens Jira: **SHOP-301 — Admin SPA for the Django catalog**. Next sprint's task: a separate Vite app, JWT auth, a paginated products table, mock APIs so you can develop without the backend running. You clone `courses/react-intermediate/examples`, run `npm install`, `npm run dev` — port **5174**, not 5173. Requests to `/api` go to **:8092**, not FastAPI's **:8090**. The console says "MSW disabled" — that's fine for now.

react-intermediate is a **continuation** of [`react-basic`](../react-basic/README.md), not a rewrite from scratch. Same React 19, Vite, TypeScript, TanStack Query, React Router — plus MSW, react-hook-form, Zustand, virtualization. The default backend is Django DRF [`deploy/django`](../../deploy/django/README.md); FastAPI [`deploy/fastapi`](../../deploy/fastapi/README.md) sticks around for contract comparisons from [18-cors-fastapi.md](../react-basic/18-cors-fastapi.md).

## What you'll learn

- How **react-intermediate/examples** differs from react-basic.
- Port **5174**, proxy `/api` → Django **:8092**.
- New dependencies: **MSW**, **react-hook-form**, **Zustand**, **@tanstack/react-virtual**.
- Conditionally starting **MSW** via `VITE_ENABLE_MSW=true`.
- A quick environment check before labs 03–13.

## Proxy to Django :8092

[`examples/vite.config.ts`](examples/vite.config.ts):

```typescript
server: {
  port: 5174,
  proxy: {
    "/api": {
      target: "http://localhost:8092",
      changeOrigin: true,
    },
  },
},
```

From the frontend: `fetch("/api/v1/products/")` → Vite forwards it to `http://localhost:8092/api/v1/products/`. CORS isn't an issue in dev — the browser sees a **same-origin** request to `:5174`.

Comparison with react-basic:

```text
react-basic:     /api  →  localhost:8090  (FastAPI)
react-intermediate: /api  →  localhost:8092  (Django DRF)
```

Don't mix up ports across projects — each course has its own `examples/`.

## MSW: structure and enabling it

```text
examples/
  public/
    mockServiceWorker.js    # generated by npx msw init
  src/
    mocks/
      browser.ts            # worker for the browser
      handlers.ts           # HTTP handlers
```

[`handlers.ts`](examples/src/mocks/handlers.ts) already contains:

- `GET /api/v1/products/` — paginated mock catalog;
- `POST /api/v1/auth/login/` — `admin@shop.local` / `admin`.

[`main.tsx`](examples/src/main.tsx):

```tsx
async function enableMocking() {
  if (import.meta.env.VITE_ENABLE_MSW !== "true") {
    return;
  }
  const { worker } = await import("./mocks/browser");
  return worker.start({ onUnhandledRequest: "bypass" });
}

enableMocking().then(() => {
  createRoot(document.getElementById("root")!).render(/* ... */);
});
```

**To enable MSW:**

```bash
# Windows PowerShell
$env:VITE_ENABLE_MSW="true"; npm run dev

# Linux/macOS
VITE_ENABLE_MSW=true npm run dev
```

Or create `.env.local`:

```env
VITE_ENABLE_MSW=true
```

`onUnhandledRequest: "bypass"` — requests with no handler pass through to the real API (Django). Handy for adding mocks incrementally.

### Checking MSW

1. Start with `VITE_ENABLE_MSW=true`.
2. DevTools → Console: `[MSW] Mocking enabled`.
3. Network → the products request shows `(from service worker)`.

## Switching between real API and mock

| Mode | Django :8092 | MSW |
|-------|--------------|-----|
| Django only | `docker compose up` | off |
| Mock only | not needed | `VITE_ENABLE_MSW=true` |
| Hybrid | running | MSW + `bypass` for unmocked routes |

A common code review question: "Why not just hardcode JSON in components?" MSW keeps the **API contract** at the HTTP level — closer to integration than `if (DEV) return fakeData`.

## Common mistakes

1. **Opened 5173** — react-intermediate listens on **5174**. That's a different process or a stale bookmark.

2. **Proxy pointing at 8090** — you copied `vite.config.ts` from react-basic. Products return 404 — Django is on **8092**.

3. **MSW won't start** — you forgot `mockServiceWorker.js` in `public/`. Run `npx msw init public --save` in `examples/`.

4. **`.env` isn't picked up** — it needs the `VITE_` prefix and a dev server restart.

5. **Two QueryClients** — don't create a second one in a feature; keep one in `main.tsx`.

6. **Node 18** — `package.json` engines requires `>=20`; you'll get odd Vite 6 errors.
