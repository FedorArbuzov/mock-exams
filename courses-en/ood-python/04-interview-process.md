# 04. Process: 45 minutes of an OOD interview

## Intro

Structure matters more than the number of classes. The interviewer expects a **dialogue**, not a monologue in code.

---

## Timeline

| Min | Action |
|-----|----------|
| 0–5 | Restate the problem, **clarify** scope |
| 5–10 | Entities, use cases (2–3) |
| 10–15 | API of public classes / methods |
| 15–35 | Implement the happy path + 1 extension point |
| 35–40 | Test or walkthrough |
| 40–45 | Trade-offs, what you would add |

---

## Questions for the interviewer

- How many users / single process?
- Is persistence needed?
- Multithreading?
- What is **out** of scope?

---

## Whiteboard / editor

1. List of classes  
2. "uses" arrows, not inheritance everywhere  
3. Method names as verbs  

---

## Sub-tasks

**Time:** ~50 min.

### 4.1 Script (20 min)

Write a 30-second intro for the Parking Lot problem.

### 4.2 Scope doc (15 min)

In scope / out of scope for an LRU cache system.

### 4.3 Timer drill (15 min)

On paper: LRU classes in 10 min without code.
